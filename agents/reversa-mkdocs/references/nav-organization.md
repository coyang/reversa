# Navigation Organization Reference

This reference defines how the MkDocs Generator builds the `nav` section of `mkdocs.yml`
based on the `granularity` setting from `.reversa/config.toml` and the actual files
discovered in `_reversa_sdd/`.

## Granularity → Nav strategy

| `granularity` | Nav section strategy | Example nav |
|---|---|---|
| `module` | One nav section per module folder, with subsection per canonical file | `Orders > Requirements`, `Orders > Design`, `Orders > Tasks` |
| `use-case` | One nav section per use case, grouped under a "Use Cases" heading | `Use Cases > User Login`, `Use Cases > Place Order` |
| `endpoint` | One nav section per endpoint, grouped under "API Endpoints" | `API > POST /login`, `API > GET /orders` |
| `hybrid` | Module at top level, nested use cases as sub-entries | `Orders > Place Order (use case)` |
| `feature` | One nav section per feature (listed in `surface.json#organization_suggestion.features`) | `Features > Authentication`, `Features > Payment` |
| `custom` | Follow `[specs].custom_folders` from `config.toml` exactly | As defined by user |

## File priority in nav

Within each unit folder, files are ordered by priority:

| Priority | File | Display name |
|----------|------|-------------|
| 1 | `requirements.md` | Requirements |
| 2 | `design.md` | Design |
| 3 | `contracts.md` | Contracts |
| 4 | `flows.md` | Flows |
| 5 | `tasks.md` | Tasks |
| 6 | `edge-cases.md` | Edge Cases |
| 7 | `decisions.md` | Decisions |
| 8 | `legacy-mapping.md` | Legacy Mapping |
| 9 | `questions.md` | Open Questions |
| 10 | `screens.md` | Screens |

Only include files that actually exist. Skip missing files silently.

## Global sections (always at top, in this order)

```
1. Home (index.md, generated by the agent)
2. System Overview
   - Architecture (architecture.md)
   - Domain Model (domain.md)
   - Code Analysis (code-analysis.md)
   - Inventory (inventory.md)
   - Dependencies (dependencies.md)
3. Architecture (C4)
   - Context (c4-context.md)
   - Containers (c4-containers.md) [if exists]
   - Components (c4-components.md) [if exists]
   - Full ERD (erd-complete.md) [if exists]
4. <Unit sections — depends on granularity>
5. Cross-cutting concerns
   - State Machines (state-machines.md) [if exists]
   - Permissions (permissions.md) [if exists]
   - Architecture Decisions (adrs/*.md) [if exists]
   - Database (database/*.md) [if exists]
   - Design System (design-system/*.md) [if exists]
   - UI / Screens (ui/*.md) [if exists]
6. Traceability
   - Code-Spec Matrix (traceability/code-spec-matrix.md) [if exists]
   - Spec Impact Matrix (traceability/spec-impact-matrix.md) [if exists]
7. Gaps & Quality
   - Gaps (gaps.md) [if exists]
   - Confidence Report (confidence-report.md) [if exists]
8. Migration [if _reversa_sdd/migration/ exists]
   - Brief (migration/migration_brief.md)
   - Strategy (migration/migration_strategy.md)
   - Target Architecture (migration/target_architecture.md)
   - ... (other migration artifacts)
9. Forward Features [if _reversa_forward/ exists]
   - <feature-1>/*.md
   - <feature-2>/*.md
```

## Example: Nav for `module` granularity (English)

```yaml
nav:
  - Home: docs/index.md
  - System Overview:
    - Architecture: architecture.md
    - Domain Model: domain.md
    - Code Analysis: code-analysis.md
  - Modules:
    - Authentication:
      - Requirements: authentication/requirements.md
      - Design: authentication/design.md
      - Tasks: authentication/tasks.md
    - Orders:
      - Requirements: orders/requirements.md
      - Design: orders/design.md
      - Tasks: orders/tasks.md
      - Contracts: orders/contracts.md
  - Database:
    - ERD: database/erd.md
    - Data Dictionary: database/data-dictionary.md
  - Traceability:
    - Code-Spec Matrix: traceability/code-spec-matrix.md
  - Gaps & Risks:
    - Gaps: gaps.md
```
