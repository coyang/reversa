# 类比指南

不确定该调用哪个智能体？激活指南：

```
/agents_help
```

它用现实世界的类比解释每个智能体。但既然你已经在这里了，下面是完整说明：

---

## 完整团队及其类比

### 🎼 Reversa：乐队指挥

指挥不演奏任何乐器。他们掌握整部乐谱，告诉每个人何时进入、以何种顺序、何种节奏。没有指挥，每个乐手都会自顾自地演奏而无法彼此配合。

> 使用 `/reversa` 启动或恢复完整的分析。它会为你处理整个流程顺序。

---

### 🗺️ Scout：房地产经纪人

经纪人对房产进行初次巡视。不开抽屉、不读文件、不碰任何东西。只是绘制地图：有多少个房间、在哪个街区、有哪些设施、整体状况如何。

> 在项目开始时使用 Scout。它生成项目清单，但不深入代码逻辑。

---

### ⛏️ Archaeologist：考古学家

考古学家耐心地逐层挖掘地层。对发现的每件文物进行编目：尺寸、材质、位置、形状。不解读文明，只精确描述那里有什么。

> 使用 Archaeologist 逐模块分析代码。每个会话分析一个模块以节省 token。

---

### 🔍 Detective：福尔摩斯

福尔摩斯在考古学家之后登场。看着已编目的文物问道：*"但这个为什么在这里？谁把它放在这里的？这揭示了关于住在这里的人什么样的信息？"* 不挖掘，而是解读。

> 在 Archaeologist 之后使用 Detective。它提取隐式的业务规则，像读日记一样阅读 git 历史，重构那些从未被文档化的决策。

---

### 📐 Architect：制图师

制图师实地考察一个地区后制作正式地图：平面图、立面图、结构图。从未踏足过那里的人也能仅通过地图理解一切。

> 在 Detective 之后使用 Architect。它将一切综合为 C4 图、完整 ERD 和集成地图。

---

### 📝 Writer：公证人

公证人将发现的内容转化为正式、精确、可追溯的合同。每条条款都有声明的置信度等级。这份文档是一份合同：AI 智能体可以据此重新实现整个系统。

> 在 Architect 之后使用 Writer。它生成 SDD 规范、OpenAPI 和带有代码追溯性的用户故事。

---

### ⚖️ Reviewer：规范审查员

Reviewer 拿着 Writer 的合同，试图从中找出漏洞：*"这是矛盾的。这一点没有证据。如果用户做了 X，这条规则就不成立了。"* 不是为了破坏，而是为了确保最终站得住脚的东西是牢固的。

> 在 Writer 之后使用 Reviewer。它严格审查规范，重新分类置信度，并提出需要人工验证的问题。

---

### 🖼️ Visor：法医插画师

法医插画师只处理图像。接收系统截图，忠实地重建界面：屏幕、表单、导航流程。不需要系统正在运行，只需要照片。

> 当你有截图可用时使用 Visor。它无需访问系统就能文档化 UI。

---

### 🗄️ Data Master：地质学家

地质学家绘制地下的地图：没人看到但却支撑一切的层。表、关系、约束、触发器、存储过程。支撑应用的隐形基础。

> 当 DDL、迁移脚本或 ORM 模型可用时使用 Data Master。

---

### 🎨 Design System：造型师

造型师对衣橱进行分类：调色板、字体、间距、设计 token。支配系统外观的"时尚规则"。

> 当 CSS 文件、主题或界面截图可用时使用 Design System。

---

## 推荐顺序

```
/reversa → 自动编排一切

或者手动控制：
Scout → Archaeologist（N 次会话） → Detective → Architect → Writer → Reviewer

任何阶段均可选：
Visor · Data Master · Design System
```
