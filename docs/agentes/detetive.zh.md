## 功能说明

Detective 在 Archaeologist 之后登场。看着所有已被编目的内容问道：*"但这个为什么在这里？谁把它放在这里的？这揭示了关于构建这个系统的人什么样的信息？"*

它不再挖掘更多代码。它解读已被挖掘出的内容。它是提取从未被文档化的隐性知识的专家：隐藏在条件语句中的业务规则、只存在于 git 历史中的架构决策、出现在验证逻辑中却没有任何注释的约束。

---

## 分析内容

### Git 考古学

Detective 像读项目日记一样阅读提交历史：

- 揭示业务或技术决策的提交信息
- 修复/热修复提交：表明"本应正常工作但却没做到"的行为
- 大型重构：表明从未被文档化的需求变更
- 带有明显原因的还原提交
- 所有这些都成为追溯性 ADR 的素材

### 隐式业务规则

- 包含领域逻辑的复杂条件判断
- 模型中的验证和约束
- 包含业务名称的常量和枚举（那些能揭示领域思维方式的常量）
- 旧注释：它们是过去意图的证据
- TODOs 和 FIXMEs：未实现的意图，可能揭示被遗忘的需求

### 状态机

对于每个包含状态/状态字段的实体，Detective 会绘制：

- 所有可能的值
- 允许的转换及其触发条件
- Mermaid 状态图

### 权限和角色

- 系统中的用户角色
- 每个角色的权限
- 对功能和数据的访问限制
- 全部以权限矩阵格式呈现

## 关于置信度的说明

Detective 对[置信度等级](../escala-confianca.md)要求严格。它提取的大部分内容都是 🟡 推断的，它自己也知道这一点。其艺术在于正确推断，并诚实地标记存在不确定性的地方。

从代码推断出的业务规则在被真正了解业务的人验证之前，都只是假设。
