# 使用方法

## 激活 Reversa

安装完成后，在 AI agent 中打开项目并激活 Reversa：

=== "Claude Code / Cursor / Gemini CLI"

    ```
    /reversa
    ```

=== "Codex 及不支持斜杠命令的引擎"

    ```
    reversa
    ```

就这么简单。Reversa 会接管并从那里协调整个分析过程。

---

## 激活后会发生什么

Reversa 会检查是否有正在进行的分析：

**首次使用：** 它会为你的项目创建一个个性化的探索计划，提交给你批准，然后从第 1 阶段开始分析。

**恢复会话：** 它会读取保存在 `.reversa/state.json` 中的检查点，精确地从上次中断的地方继续。不管你关掉了编辑器、重启了机器，还是把它放着休眠了三天，都无所谓。

---

## 完整分析的典型流程

```
你输入 /reversa
        ↓
Reversa 创建探索计划
        ↓
你审查并批准计划
        ↓
Scout 绘制项目概貌
        ↓
Reversa 展示 Scout 摘要，你选择文档级别
        ↓
Archaeologist 逐模块分析
        ↓
Detective 和 Architect 解读发现的内容
        ↓
Writer 生成规格说明（一次一个，需你批准）
        ↓
Reviewer 审查一切并提出验证问题
        ↓
规格说明就绪，在 _reversa_sdd/ 中
```

整个过程是渐进式和对话式的。你不需要全程在场：Reversa 会在需要你的时候通知你。

---

## 需要多长时间？

取决于项目规模，但大致规则如下：

| 项目规模 | 预估时间 |
|----------|----------|
| 小型（少于 10 个模块） | 2 到 4 个会话 |
| 中型（10 到 30 个模块） | 5 到 10 个会话 |
| 大型（30 个以上模块） | 10 个以上会话 |

Archaeologist 有意地每个会话只分析一个模块，以保留上下文。对于大型项目，你需要多次恢复，但每次恢复都是自动且无损的。

---

## 小贴士：上下文溢出

如果会话变得太长，上下文开始耗尽，Reversa 会自动保存检查点并警告你：

> "我在这里暂停一下。所有内容已保存。在新的会话中输入 `/reversa` 即可继续。"

不必惊慌。不会丢失任何内容。稍后继续就好。

---

## 文档级别

Scout 完成后，Reversa 会展示一个摘要，说明它发现了什么（模块数量、集成情况、是否存在数据库），并询问你希望为项目生成什么级别的文档：

| 级别 | 适用场景 | 生成内容 |
|------|----------|----------|
| **Essential（基础）** | 简单项目、脚本、原型 | 核心产物：代码分析、领域、架构、SDD spec |
| **Complete（完整）** | 中型项目、小型团队（默认） | 基础级别的全部内容 + C4 图、ERD、ADR、OpenAPI、用户故事和可追溯性矩阵 |
| **Detailed（详细）** | 企业系统、多团队 | 完整级别的全部内容 + 每个函数的流程图、扩展 ADR、部署图和强制交叉审查 |

选择会保存在 `.reversa/state.json` 中，所有后续 agent 会自动遵循。如果在分析开始后需要调整，只需编辑该文件中的 `doc_level` 字段即可。

---

## 手动激活特定 agent

如果你想在绕过协调器的情况下单独运行某个 agent：

```
/reversa-scout
/reversa-detective
/reversa-data-master
```

当你已经有正在进行的分析，但出于某种特定原因想运行特定 agent 时，这个方法很有用。
